# CompIntel3 架构

CompIntel3 是单用户本地编程对战工作台。C++/WinRT 与 WinUI 3 负责窗口、编辑器、棋盘和回放；标准 C++ 游戏核心负责规则；Win32 运行器负责编译和逐回合通信。应用不需要 Web 服务、数据库服务器或评测队列。

## 文件结构

| 路径 | 职责 |
| --- | --- |
| `src/main.cpp` | WinUI 应用启动和窗口生命周期 |
| `src/ui/MainWindow.*`、`src/ui/UiMarkup.h` | 原生界面、对局调度、后台编译与思考、回放控制 |
| `src/ui/Storage.*` | 程序版本、编辑草稿、设置和对局记录的本地持久化 |
| `src/core/Game.*` | 五子棋和路墙棋的状态、动作校验、胜负判断、撤回及内置策略 |
| `src/runtime/PlayerProcess.*` | MSVC 环境发现、编译、玩家进程和标准流通信 |
| `examples/`、`src/Samples.rc` | 两种游戏的 C++20 示例与嵌入资源 |
| `tests/` | 游戏规则、运行器异常路径和示例程序的实际交互检查 |
| `scripts/build.ps1` | 依赖还原、应用构建与测试入口 |

## 编译和版本

`Compiler::Compile` 接收 UTF-8 源码，为每次编译创建独立的 `build-…` 目录，保存 `player.cpp` 并生成 `player.exe`。源码限制为 256 KiB；写入编译文件前，将 CRLF、单 CR 和 LF 统一为 LF，兼容 WinUI `TextBox` 的行尾格式。默认通过 `vswhere` 定位安装了 C++ 工具的 Visual Studio，再调用 `vcvars64.bat` 获取 x64 编译环境；显式填写 `cl` 或 `cl.exe` 也使用该流程。指定 `clang++` 或 `g++` 时直接调用相应工具。

编译器由 `CreateProcessW` 启动，源码和输出路径作为正确引用的参数传递，不拼入 shell 命令。编译子进程使用独立 Job Object，最多等待 45 秒，日志最多保存 256 KiB。只有退出码为零且可执行文件存在时，编译结果才成功。调用方在后台线程编译，成功后保存新的程序版本。

## 对局进程生命周期

1. `Start` 创建重定向标准输入、标准输出和标准错误的暂停进程，将其加入 Job Object。此时玩家尚未执行。
2. 调度器在该程序第一次行动时，将初始化信息和必要的对手首步一起交给 `Turn`；以后只传入对手最近一步。初始化协议见 [protocol.md](protocol.md)。
3. `Turn` 写入输入并恢复进程，轮询完整输出行、标准错误、CPU 用时和墙钟截止时间。输出一行后暂停主进程，再交由游戏核心解析和校验动作。
4. 运行错误、超时、超长输出或多余输出会终止该玩家的 Job。合法但不符合游戏规则的动作由调度器判负。
5. 正常终局、停止或切换对局时调用 `Stop`，终止整个 Job；不发送额外的游戏结束消息。析构仍会清理进程。

`Turn` 是同步工作接口，应在后台线程调用。它允许另一个线程调用 `Stop` 中断等待；同一个玩家同时启动第二个 `Turn` 会立即返回错误。启动过程与停止操作使用代际检查，避免已取消的启动重新发布进程。

## 资源控制的真实范围

| 项目 | 默认行为 |
| --- | --- |
| 每回合主进程 CPU | 100 ms |
| 整局主进程累计 CPU | 5 s |
| 每回合墙钟截止时间 | 1 s；调用方可设置 |
| 标准输出 | 每回合一行，包含换行最多 64 字节 |
| 标准错误 | 持续排空；整局最多保留 16 KiB，超出显示截断提示 |
| 内存 | 单进程及整个 Job 的提交内存上限均为 256 MiB |
| 进程数量 | 每个玩家 Job 最多 8 个活动进程 |
| 停止与退出 | 终止玩家 Job 中的全部进程；关闭 Job 句柄也会清理 |

CPU 统计使用主进程的 `GetProcessTimes`，回合间暂停使用 `NtSuspendProcess` / `NtResumeProcess`。这些原生入口不可用时拒绝启动；活进程暂停或恢复失败时返回错误。CPU 限制由轮询检查，有操作系统计时和调度粒度，不能视为硬实时截止时间。子进程 CPU 不计入上述主进程 CPU 预算，回合间暂停也不覆盖子进程；Job 的内存、数量和清理约束覆盖子进程。

Player 使用当前登录用户权限运行，可以访问该用户可访问的文件、网络和系统资源。这些措施用于本机可信程序的调试和失控清理，不提供恶意代码隔离，也不等价于原 CompIntel 的 Linux `go-judge` 沙箱。需要处理不可信提交时，应另接独立隔离的评测服务。

## 状态与回放

游戏核心不依赖 WinUI、进程或持久化。界面把人类输入、内置策略和程序输出统一转换为 `Move`，通过同一套规则更新局面。回放保存初始游戏类型和动作序列，通过规则核心逐步重建棋盘；程序版本保存编译时的源码，后续编辑创建新版本。

当前实现面向本机使用，不包含原 Web 平台的账号、邮箱验证、管理员、云端评测、排行榜或多人在线服务。
